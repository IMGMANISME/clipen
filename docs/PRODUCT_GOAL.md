# Clipen 產品需求基線

狀態：重新規劃，尚未選定新架構或開始新實作。
更新：2026-08-27

本文件保留使用者的產品需求。舊架構文件、契約、測試與 CLI 已退出工作專案；
不保留額外備份；Git 中的舊版本只供歷史查考，不是新版本的實作依據。

## 三個設計重點

- **架構**：責任清楚、資料流簡單、容易測試與替換。先確認需要哪些邊界，
  再選語言、框架與 AI 接入方式；不預設沿用舊 Python CLI 或 Tauri 方案。
- **效能**：量測從素材匯入到可接手初剪的時間、各階段耗時、記憶體、
  磁碟用量及 AI 使用成本。依素材規模與測試硬體建立目標，不先捏造速度保證。
- **UX**：讓使用者用最少設定完成工作；進度、取消、錯誤與恢復要易理解。
  技術選擇不應成為每次剪片的負擔，Clipen 不提供完整手動剪輯介面。

## 要解決的工作

使用者提供原始影片，AI 完成大部分剪輯工作；使用者把結果帶到 DaVinci Resolve，
進行少量調整與最終發布。原始素材不被覆寫，生成結果中的編輯內容仍可在 Resolve
手動修改，不能以單一壓平影片代替可編輯成果。

Resolve 是優先交付對象。實際交換格式、支援的編輯操作與相容性範圍重新評估，
必須以真實匯入與手動修改驗證，不能直接承接舊規格的保證。

## 保留的功能需求

- 支援使用者自己的 AI，包含 Local LLM／Token API；Codex、Claude、Gemini
  等接入方式列入評估，不假設相同登入方式或全部都必須在第一版完成。
- 剪輯習慣可儲存成可建立、讀取、重用的 Editing Skills；
  具體格式與執行方式尚未決定。
- 使用者可指定範本作品資料夾，讓 AI 分析風格並產生可確認的 Skill 草稿。
  範本與待剪素材分開，不因放入資料夾就自動上傳、付費或取得素材再利用權。
- 輕量看片的分析範圍與未知項目要明確；不宣稱能從成片還原完整原始剪輯工程。
- 日常修改與最終製作交給 Resolve；Clipen 專注素材、AI 初剪與順暢交接。

這些是需要重新排序的需求，不是已完成的功能或已鎖定的第一版範圍。

## 長期成果目標

希望 AI 完成超過 80% 的最終製作工作。以人工時間節省衡量，而非文件數量、
程式碼行數或與某支成片的逐格相似度：

```text
完成度 = 1 -（從 AI 初剪收尾的人工時間 ÷ 從零手剪的人工時間）
```

人工收尾時間不超過基準的 20%，代表達到 80% 節省目標；希望持續超過此門檻。
50% → 65% → 75% → 80% 只保留為逐步驗證的方向，
不沿用舊路線圖的實作階段，也不代表目前已達到任何品質里程碑。

## 下一次規劃的邊界

先選一種影片與一個使用情境，定義從匯入到 Resolve 接手的最小流程、
效能測量方式和必要的模組責任。形成精簡方案後再決定實作範圍。
舊實作移除後，從此需求基線重新規劃與重做；目前尚未開始新實作。
