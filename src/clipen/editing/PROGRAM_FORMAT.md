# 節目式旅遊剪輯

使用者在 2026-10-19 的明確方向：不要字卡，要像 Joeman 那樣有節目感；現在的元件太陽春，故事沒有串起來。
本模式把單一事件的對話、期待、體驗和回應放在前面。畫面與配樂支援這條內容線。

## 敘事交付

- `creative_direction` 由使用者的開始命令帶入，與 run_created 同一交易保存；LLM 的規劃不能改寫這項偏好。
- `plan_episode` 指定本段主題、觀眾想知道的問題、最後的回應，並把每個鏡頭對應到實際用途。
- 引用口語需連到當下保留的 cue；跨來源片段不能只靠剪接假裝同一件事的反應。
- 來源範圍、順序、時長或原音是否被靜音改變後，規劃失效；純顏色、字幕呈現不會迫使重填故事。
- 冷開場和回扣可以使用同一來源，必須提供 reprise_reason；這不是讓重複畫面填時長的品質許可。
- 節目結構是可檢查的編輯決策，不是自動證明影片有趣的分數。

## 畫面呈現

本模式停用 add_title / add_clip_title。舊字卡未移除也不能完成預覽。
字幕採粗描邊白字、句內黃色重點、短促入場動態與底部安全區，沒有底板或獨立章節卡。
使用原生 RGBA 事件渲染，不要求使用者額外安裝 libass；一般與大量字幕使用同一呈現路徑。
字幕可分頁以維持兩行閱讀；ASR 段內的分頁時間依字數估算，未宣稱是逐字精準對齊。

## 口語與聲音

`include_drafts=true` / `allow_asr_draft=true` 允許先做有來源的低信心字幕草稿，
其來源、信心狀態、修改與時間估算方式保留在原生匯出，UI 顯示待核對段數。
這個選項不會改寫人類確認狀態。草稿可改標點、分句，不能加入來源不存在的價格、評價或台詞。
ASR 與影片時間邊界在一影格內的量化差會顯式記錄並限制在鏡頭內；真正被剪掉的話仍不能當完整句。
目前沒有聲音感知輸入，因此辨識正確性、音樂聽感與最終混音仍不能冒稱已通過聽音驗收。

## 參考與這次的樣片

參考連結：[Joeman 樂園對決](https://www.youtube.com/watch?v=dFujMyICK-U)。
已核對其公開標題的樂園比較企劃；工具未能取得完整原片，沒有聲稱逐鏡分析其剪點或直接複製其元件。
上述字幕元件及工作流程是 Clipen 的原創實作，節目核心依使用者這次的明確描述設計。

本次用實際午餐素材做小段落：午休玩笑冷開場 → 餐點介紹 → 飲料與吹冷氣的期待 →
餐桌互動 → 回扣。先以單一事件驗證節目感，不再壓縮五天行程成一段音樂蒙太奇。
樣片是本次對話直接使用相同工具製作，不是新一輪自主 Codex 執行的驗收證明。

## 自主製作與使用者基準

瀏覽器的「以這版作為節目基準」只接受已完成的指定 revision，需有效本機 session 與 CSRF。
這是使用者選擇呈現方向，不會將 ASR、混音或模型自評升格為人工驗收。LLM 的 MCP 工具沒有此寫入權限。
下一次開始工作時，基準內容與 run_created 同一交易固定保存；之後換基準不會改變進行中的工作。
原生時間軸匯出也會帶上該次固定的參考。

`get_program_reference` 提供參考的段落安排、字幕呈現與來源 ID。原片台詞是範例，不是新片腳本。
`search_source_dialogue` 可用關鍵字或空查詢瀏覽目前素材的逐字稿，包含相鄰句、來源時間、信心與核對狀態，
不受先前候選視窗限制。預設排除基準使用的原片，讓自主測試必須找另一個事件；素材不足時可以明確包含，
但不能把重播基準宣稱為新的選材成果。LLM 接著註冊來源範圍並看圖，判斷同一事件與因果，而不是把文字命中當作事實。

執行順序由模型決定；可走「搜尋對話與看圖 → 選材與精剪 → plan_episode → 字幕、畫面與聲音 →
輸出 → 逐鏡與逐字幕檢視 → 修正 → 再輸出 → 匯出及完成」。工具錯誤仍留在同一次工作內修正。
付費工作不自動重送；用量、錯誤與剩餘預算照實保存。未通過完整取樣與當前版本檢查時不能完成，先前成功樣片保留。
finish_edit 會先保存最終版可編輯時間軸與使用音訊的來源授權，再凍結結果；不依賴模型記得另外呼叫匯出。

這個自主流程目前交付 30–75 秒的節目樣片。完整長片製作仍需在樣片品質可重現後擴展，
本功能沒有把短樣片限制偷偷移除，也不以工具數量宣稱完整節目品質已達成。

### 自主實測揭露的 ASR 問題

第一輪自主製作把 `poppy` 連續重複等可疑草稿照印成字幕，顯示來源可追溯不等於適合展示。
現在對明顯的重複拉丁詞提供 quality_flags；未核對且包含這種訊號的字幕會要求修正。
這個保守訊號不宣稱實際口語一定錯誤，也不擋已由人核對的重複發言。
`source_excerpt: {start, end}` 可只引用原句的字元區間，不得改寫；時間仍是 ASR 段內字數估算，
完整來源句、引用區間與估算方式全部保留。模型也可以不加這段字幕並保留原音。

`plan_episode` 的段落可明確指定時間範圍，在同一連續鏡頭內安排不同用途；不必為填敘事欄位而製造剪點。
通用字卡編輯不能覆寫有來源的節目字幕；改文字、摘錄與呈現需走 replace_subtitles。

## 2026-10-19 自主驗證結果

已認可的 34.8 秒午餐基準維持原版。另以真實 Codex MCP 工作驗證兩輪：

- 第一輪 56 次工具操作、一次預覽，完成 47.6 秒街頭對話，但印出可疑重複 ASR；據此新增品質提示、來源摘錄及對應回歸測試。
- 修正版第二輪 50 次工具操作、一次預覽，模型自行搜尋並選取另一支原片，完成 55.633 秒漢堡試吃事件。
  三個片段、六頁字幕；模型自行引用兩段 source_excerpt，安排期待、入口與詢問、正面回應，保留現場原音、選擇不加配樂。
  完成當前 revision 的輸出、逐鏡首中末與字幕取樣、敘事判斷及技術檢查。這輪未由外層對話代選鏡頭或修改時間軸。
- 第二輪工作在「完成時強制匯出」修正前已啟動，因此外層交付步驟補存相同 revision 的原生 JSON；影片、字幕、聲音與模型審片沒有變動。
  後續工作由 finish_edit 自動保存交付檔，實際渲染整合測試已覆蓋。
- 使用者基準仍指向原本認可的版本；新自主樣片沒有自動升格為使用者認可。兩輪各自保存實際 Token 用量，未以零用量替代未知值。

回歸測試共 478 項通過，前端 build / lint 通過。這些是功能與執行證據；
新片的節奏、娛樂性與 ASR／混音聽感仍需觀眾驗收，沒有宣稱已可穩定製作完整長片。

## 完整後製需求與測試入口

使用者進一步要求配樂、精剪與轉場，不能只交字幕。新的網頁開始命令固定帶入
`production_requirements: {music: true, editing: true, transitions: true}`，與該次工作一起保存。
舊工作維持原需求，不會把舊的無配樂結果重新宣稱為完整後製。

驗證檢查實際時間軸：配樂需要放置在片內且具作者、來源及授權資料；讀取曲目清單或只有現場聲不算。
剪輯需要更動來源序列；只加字幕不算。轉場需位於實際剪點，只有片尾淡出不算。
目前視覺轉場支援淡黑與淡白，具體時機與長度仍由模型決定；不宣稱支援尚未實作的轉場種類。
缺項會阻止完成，模型可在同一工作補齊；失敗時保留先前結果。

結果與原生匯出新增 production_contents：實際剪點、配樂時段／音量／人聲壓低、來源授權、轉場時間與畫面動態。
這些是內容盤點，不是聽感或美感分數。

測試時停止舊 Clipen，在同一工作區重新執行 `clipen codex`，刷新網頁。
在同一作品勾選額度授權，按「製作完整後製樣片」。完成後查看「本版實際後製」，再播放確認人聲、節奏與轉場。
既有 MP4 不會因為更新程式自動增加音樂，必須重新生成。沒有重跑付費 AI 就不宣稱已驗證新版模型的選曲品質。
