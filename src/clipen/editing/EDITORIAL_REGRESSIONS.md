# 剪輯品質失敗的回歸紀錄

工具呼叫數、預覽次數、完整解碼都不能證明影片值得看。這次修正依據實際樣片的三種失敗：
空景／交通鏡頭取代主要互動、地點字卡錯配店面、剪斷口語後放棄全部字幕。

| 原本行為 | 現在可執行的修正 | 驗證 |
| --- | --- | --- |
| 反覆看相同單張候選圖 | `inspect_candidates` 批次看來源頭／中／尾；`inspect_cut` 比對來源與成片 | 真正取樣來源與 MP4；仍不冒稱連續動作感知 |
| 任一成片截圖就可完成 | 所有鏡頭頭／中／尾和所有文字中點都須被檢視 | 缺少時間點及文字 ID 明列在 render_review；修改後失效 |
| 審片只寫泛泛完成 | `review_cut` 列出逐鏡觀察與每張字卡依據 | 未解決問題阻擋完成；同版不能只改評語清除問題 |
| 字卡跨到其他店面 | `add_clip_title` 限定在同鏡並記錄依據 | 時間越界被拒絕；事實正確與否仍需實際畫面判斷 |
| 截斷句子消失 | 回傳完整口語來源範圍；`replace_clip_source` 可擴回原片 | 原片邊界、時間基準、12 秒完整段落都有回歸測試 |
| 待核對逐字稿被當成不存在 | status=needs_review 回傳 provisional_text 和來源時間 | 不納入已核對字幕、不改寫使用者確認狀態 |
| 強制八鏡、十秒內，妨礙完整發言 | 改為 1–30 鏡、單鏡最長 30 秒 | 短樣片總長仍為 30–75 秒；完整長片尚未實作 |
| 進入末鏡的淡轉被誤稱片尾淡出 | `set_fade` 明確區分鏡頭頭／尾 | FFmpeg 濾鏡時間與實際跨剪點畫面測試 |
| 搜尋新風格卻回傳所有舊歌 | 只回傳當次候選，舊曲另列 ID；共用風格詞彙 | 舊歌不混入當次結果；保留實際來源與授權 |
| 有圖片的成功工作被報協定錯誤 | 剪輯工作解析器使用一致的 32 MiB 上限 | 大於 2 MB 的成功紀錄能保留真實用量 |

這些能力仍有明確邊界：模型對取樣圖的判斷可能錯誤；相同模型自評不是獨立驗收；
目前 Codex 剪輯輸入沒有聲音感知。公開曲庫逾時不得宣稱找到符合風格的配樂。
未核對的語音不得因為要完成樣片就假裝已核對，亦不能用技術通過替代人工觀看片驗收。

本次實際驗證額外發現：單一 agent 即使完成逐鏡自評，仍可能保留過多交通／空景。
因此另外做了本次對話的導演修訂，保留第一輪供比較；這項人工監督的修訂不能被當成
產品已具備可靠自主美感評審的證據。

本機驗證：`.venv/bin/python -m unittest discover -s tests/python -q`；
前端在 `apps/web` 執行 `npm run build` 與 `npm run lint`。

參考：
[Adobe B-roll](https://www.adobe.com/creativecloud/video/discover/b-roll.html) 說明補充鏡頭應支援主要事件與敘事意義；
[B-Script](https://arxiv.org/abs/1902.11216) 探索逐字稿及敘事上下文驅動的 B-roll 編輯。

實際多鏡合成另重現 AAC encoder padding 導致跨批次時間戳間隙；
以每批時間軸精確時長寫入 concat manifest 修正。29.97 fps 來源、九個非整影格
來源範圍轉成 30 fps 時間軸的測試，會核對平均格率、精確格數、影音長度與完整解碼。
背景預覽事件與前景工具紀錄的序號配置改成單一原子寫入，四個連線同時寫入的
回歸測試涵蓋取消預覽時可能出現的序號碰撞。
