# 今天吃哪邊

紅黃菜單花章、雙方料理識別與粗字反應，像一場餐桌節目。

## 套用與工具

本 Skill 與 manifest.json 一起隨製作工作凍結。從 get_edit_status 讀取本次需求、片長、既有時間軸與手動參考；使用者本次指示優先。
使用共用製作 Skill 的來源、版本與權限流程，以現有 MCP 工具執行。本文件的資源路徑均相對於製作套件根目錄，透過 read_production_skill 讀取。
先看 `assets/style-tpl-food.png`，並讀 `visual_styles.json` 與 `font_styles.json` 中選定的設定。
本套畫面風格為 `tpl-food`，預設字體為 `japanese`；使用者可另外換字體。
用 list_program_components 選語意元件，透過 add_program_component / update_program_component 編輯；本套 presets 的構圖只是參考；新增時看過該鏡畫面後明確指定 x、y，避開人臉、動作與字幕，不讓每個元件都落在同一角。

## 故事與節奏

交代這餐的期待或兩個可比較選擇，保留等待、第一口與真實反應；有比較就回到最初標準，沒有兩方素材則改成單次體驗，不假造對決。

先看餐點與人物期待，再留完整第一口及反應；用料理細節補充評語。兩方比較維持相同項目順序，避免只用漂亮食物鏡頭堆疊。

## 字幕與後製畫面

實際台詞才上口語字幕；impact/reaction 強調說過或發生過的重點，編輯評價明確區分。價格與品名要由店單、現場或使用者資料核對。

菜單花章的 program_title 建立本集題眼；兩方 fact/location 各自識別，headline 提問，第一口後才視需要加 impact。元件留出嘴部、表情與食物。

## 動畫與聲音

粗字有力進場，反應節點短促強調；不每一口都放爆點。比較切換可沿兩方標註的位置呼應，避免滿屏字卡中斷用餐。

輕快節拍襯托現場，第一口前可留一拍等待；保留有用咀嚼與現場反應，音效只服務真實事件，對話時降低配樂。

配樂若由使用者指定就沿用，否則使用音樂工具尋找並保存來源與授權。僅能依量測和證據調整音訊，不能宣稱已實際聆聽。

## 持續修改與驗收

繼續編輯時保留本工作的凍結 Skill，先讀目前修訂與修改要求；只修改受影響範圍，保留手動位置、字幕、音軌與未受影響的剪點。
若需要換風格，依使用者明確要求使用 restyle_program_components；不能默默改成另一套模板或重建整片。

期待、第一口、反應與結論是否連在一起？兩方比較是否公平？價格或評分有依據嗎？視覺包裝沒有擋住最值得看的反應嗎？

用 render_preview 檢查實際版面、字體、動態與剪點，再依本次修訂回看。量測成功不等於美感通過；目前不支援的元件、動畫或音訊感知需保留具體待辦。
