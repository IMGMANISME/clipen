# 任務不可能嗎

切角黑黃告示、規則標線與有力進場，把目標變成觀看動力。

## 套用與工具

本 Skill 與 manifest.json 一起隨製作工作凍結。從 get_edit_status 讀取本次需求、片長、既有時間軸與手動參考；使用者本次指示優先。
使用共用製作 Skill 的來源、版本與權限流程，以現有 MCP 工具執行。本文件的資源路徑均相對於製作套件根目錄，透過 read_production_skill 讀取。
先看 `assets/style-tpl-mission.png`，並讀 `visual_styles.json` 與 `font_styles.json` 中選定的設定。
本套畫面風格為 `tpl-mission`，預設字體為 `japanese`；使用者可另外換字體。
用 list_program_components 選語意元件，透過 add_program_component / update_program_component 編輯；本套 presets 的構圖只是參考；新增時看過該鏡畫面後明確指定 x、y，避開人臉、動作與字幕，不讓每個元件都落在同一角。

## 故事與節奏

用明確目標與可理解的條件開場，保留嘗試、受阻、調整與結果。素材沒有完成證據時保留未解結果，不能用音效和字幕假裝成功。

先讓觀眾理解規則，再濃縮重複嘗試；失敗或策略改變要保留因果。結果前留出可預期的等待，避免只挑高能片段失去過程。

## 字幕與後製畫面

規則用短資訊句呈現，台詞仍以原話字幕處理；反應大字只強調有證據的轉折，不能捏造挑戰者心聲。

切角黑黃 program_title/headline 建立任務，chapter 說明新階段，fact 呈現有依據的條件。倒數、分數與完成進度必須有來源，示例的勾選不是素材事實。

## 動畫與聲音

有力擦入與警示線條服務規則和轉折；嘗試中的一般過程保持清楚，避免每鏡撞擊。需要未支援的計時動畫時明確保留待辦。

節拍推動嘗試，受阻或揭曉前留白；保留現場判斷和結果的原音。降低刺耳來源音量，不用增加配樂音量硬蓋。

配樂若由使用者指定就沿用，否則使用音樂工具尋找並保存來源與授權。僅能依量測和證據調整音訊，不能宣稱已實際聆聽。

## 持續修改與驗收

繼續編輯時保留本工作的凍結 Skill，先讀目前修訂與修改要求；只修改受影響範圍，保留手動位置、字幕、音軌與未受影響的剪點。
若需要換風格，依使用者明確要求使用 restyle_program_components；不能默默改成另一套模板或重建整片。

沒看過原片的觀眾能說出任務、限制和結果嗎？嘗試的因果完整嗎？所有進度與分數都真實嗎？

用 render_preview 檢查實際版面、字體、動態與剪點，再依本次修訂回看。量測成功不等於美感通過；目前不支援的元件、動畫或音訊感知需保留具體待辦。
